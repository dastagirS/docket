## One-level subtickets and schema v3

Tickets now expose nullable `parent_id`. Creation accepts only an existing same-project top-level parent, checked inside the ticket/event transaction. PATCH rejects any supplied parent field, including null, so roots cannot be converted later and children cannot acquire descendants or form cycles through the API. Parent links use a nullable foreign key and an indexed `(project_id,parent_id,id)` collection filter applied before pagination/search/archive selection. Normal board/list queries still include children. Parents and children have independent versions, statuses, assignments, discussion, and archive states; relationship changes do not implicitly rewrite a parent's history. Reparenting and automatic rollups/cascades are intentionally absent.

The UI offers Add subticket on top-level tickets, parent-reference badges on board/list items, a parent navigation action on children, and paginated active/archived child lists on parents. Child lists refresh even when the parent's own version has not changed, preserving unsaved parent fields and comments. They use the existing display/page bounds rather than fetching an unbounded tree; there is no recursion or per-card parent lookup. New response fields may require updates in strict external clients; the separate Pi integration was not changed or integration-tested here.

## Local project initialization and folder defaults

`docket project init` creates a project through the existing API and atomically binds the current folder using an owner-only, versioned `.docket` JSON file. Descendants inherit it within the nearest Git boundary (64 ancestors maximum). Repeat init displays total/active/archived counts including subtickets and offers keep (default), create another, or archive-and-replace. Noninteractive repeats require an explicit choice. Scoped commands pin both server and project, verify immutable identity, and retain explicit ticket versions; explicit project/server flags remain available. Pi integration markers, ownership policies, and recovery receipts are not modified or bypassed.

A new read-only `/api/projects/{project}/stats` aggregate avoids downloading ticket bodies to count records; existing response shapes and schema version 3 are unchanged. Initialization reserves a local journal before remote writes, creates the replacement before archiving the old project with its observed version, and changes the marker only after confirmation. HTTP writes and filesystem operations are not one transaction. Partial/unknown outcomes retain `.docket.lock` and block implicit scope rather than replaying creation or guessing a board. The docs explain human reconciliation; no lock stealing, retries, automatic rollback, or idempotency claims were added.
